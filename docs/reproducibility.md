# Reproducibility guide

## Implementation status

The paper describes a Hub-hosted adapter, a `best.json` selection artifact, and
a step-3,000 `best_adapter`, but does not provide a public code or adapter URL.
This repository is an independent reference implementation reconstructed from
the paper's protocol. It is not the authors' original training code. The paper's
reported numbers are preserved in [`results/`](../results) and are not
regenerated by this code by default.

## Environment

| Component | Recommended |
|---|---|
| Python | 3.10–3.12 |
| CUDA | 12.1+ |
| Training GPU | 2× NVIDIA T4 (paper) |
| Precision | FP16 compute, 4-bit NF4 base weights |
| Optimizer | 8-bit AdamW (`adamw_8bit`) |
| Core packages | `transformers`, `peft`, `accelerate`, `bitsandbytes`, `torch` |
| Metrics | `sacrebleu>=2.4` |

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
pip install -e ".[train]"
```

`bitsandbytes` is excluded on macOS in `pyproject.toml`; 4-bit training
therefore requires Linux or Windows with a supported NVIDIA GPU.

## 1. Data layout

Arrange one CSV per language and split:

```text
data/
├── train/{hi,bn,ml,or}.csv
├── dev/{hi,bn,ml,or}.csv
├── test/{hi,bn,ml,or}.csv
└── challenge/{hi,bn,ml}.csv
```

Expected columns (names configurable in `configs/qlora.yaml`):

| Column | Required | Description |
|---|---|---|
| `image` | Yes | Image path relative to the data root, base64 payload, or data URI. |
| `caption` | Yes | English source caption. |
| `target` | Train/dev/test | Target-language reference caption. Optional for challenge. |
| `x1`, `y1`, `x2`, `y2` | Yes | Annotated region in pixel coordinates. |
| `id` | No | Row identifier; generated if absent. |

Validate the layout before training:

```bash
python scripts/validate_data.py --data-dir data
```

## 2. Region preprocessing

Every row follows the paper's pipeline:

1. Expand the annotated box by **15%** of its width and height on each side.
2. Clamp the padded box to image bounds.
3. Fall back to the full image for degenerate boxes.
4. Crop, convert to RGB, and resize as a thumbnail capped at **448×448** while
   preserving aspect ratio.
5. Normalize the **padded** box to a **0–1000** scale and place it in the prompt.

The implementation is in [`src/gabu/preprocess.py`](../src/gabu/preprocess.py)
and covered by `tests/test_preprocess.py`.

## 3. Training

```bash
gabu-train --config configs/qlora.yaml --data-dir data
```

| Paper setting | Repository setting |
|---|---|
| `google/gemma-4-E4B-it` | `model.id` |
| 4-bit NF4, double quantization, FP16 compute | `model.load_in_4bit`, `quant_type`, `double_quant`, `compute_dtype` |
| LoRA r=64, α=128, dropout 0.05 | `lora.r`, `lora.alpha`, `lora.dropout` |
| Target `q, k, v, o, gate, up, down` | `lora.target_modules` |
| 115,715 train + 3,992 dev rows | `load_training_frame`; `include_dev_in_training: true` |
| 8-bit AdamW, LR 1e-4, cosine, 5% warmup | `training.optimizer`, `learning_rate`, `scheduler`, `warmup_ratio` |
| 2 × 1 × grad accumulation 8 = 16 effective | `per_device_train_batch_size`, `gradient_accumulation_steps` |
| Max sequence length 1,024 | `max_seq_length` |
| 3,000 steps | `max_steps` |
| Gradient checkpointing | `gradient_checkpointing` |
| Seed 3407 | `seed` |
| Dev monitoring: 100 rows/language for loss | `load_monitor_frame(per_language=100)` |

The paper monitors a 400-row development loss subset and a 200-row generation
subset, and selects `best_adapter` by macro CHRF3. This reference trainer
selects by development loss and writes a `best.json` note explaining the
difference. The original adapter was the recorded step-3,000 checkpoint, not a
pinned Hub revision.

### Prompt masking

The paper explicitly states that the collator masks the rendered prompt and
supervises only the reference translation. This repository defaults to
`mask_prompt_tokens: true` and matches that behaviour.

## 4. Inference

Run one language/split worker at a time (the paper used two isolated worker
processes on two GPUs):

```bash
gabu-infer \
  --config configs/qlora.yaml \
  --lang hi \
  --split test \
  --adapter outputs/gabu-gemma4-e4b-qlora/best_adapter \
  --output-dir outputs/test_predictions
```

Repeat for `bn`, `ml`, and `or`; challenge inference covers `hi`, `bn`, `ml`.
Outputs are:

- `{lang}.jsonl` with `idx`, `ref`, and `decoded` fields per row.
- `{lang}.txt` with one decoded line per row.

Runs are resumable: existing `idx` values in the JSONL are skipped. Use
`--no-resume` to overwrite.

## 5. Evaluation

```bash
gabu-evaluate \
  --pred-dir outputs/test_predictions \
  --languages hi bn ml or \
  --output outputs/test_metrics.json
```

Metrics match the paper:

- **BLEU**: corpus BLEU, 13a tokenization, case-sensitive, single reference.
- **CHRF3**: β=3, character order 6, word order 2 (CHRF++ statistics).
- Per-language scores rounded to two decimals; macro is the unweighted mean
  over evaluated languages.

Challenge evaluation covers only Hindi, Bengali, and Malayalam because Odia
challenge references were not released.

## Fidelity and limitations

- The training budget is 3,000 steps on two T4 GPUs, a compute-driven choice;
  it is not claimed to be optimal.
- A single rank-64 adapter bounds expressivity relative to full fine-tuning.
- There is no dedicated fusion architecture; architectural ablations are
  limited.
- The evaluated adapter is the recorded step-3,000 checkpoint. A rerun may
  select a different checkpoint or none if `best.json` is not used.
- Optimizer hyperparameters beyond learning rate, scheduler, and warmup use
  library defaults.
- Checkpoint selection reuses one 200-row development subset, and the same
  image pool underlies all splits by dataset design.
- No text-only, image mismatch, or region/full-image ablations were released;
  the contribution of visual context cannot be isolated.
- Multiple seeds and human evaluation remain future work.
- The released evaluation script pulled the adapter from the Hub head without a
  pinned revision; exact reproduction requires the final adapter artifact.

## Reproduction checklist

- [ ] Four language CSVs present for each split; Odia challenge has no refs.
- [ ] Boxes are pixel coordinates and images resolve from the data root.
- [ ] Region crops use 15% padding and preserve aspect ratio.
- [ ] Joint training frame has 115,715 train + 3,992 dev rows.
- [ ] Adapter has ~139.5M trainable parameters (1.73% of 8.08B).
- [ ] Inference is greedy with at most 32 new tokens.
- [ ] Outputs are single-line target-script translations.
- [ ] Evaluation uses BLEU 13a + CHRF3 and reports macro over languages.
